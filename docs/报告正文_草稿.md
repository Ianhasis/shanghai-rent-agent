## 1. 需求与目标
**目标用户**：在上海求学或实习、首次租房的学生。  
**场景痛点**：刷 App 只能看到挂牌价，缺少“同类房大概值多少钱”的依据；在预算、面积、区域约束下筛选成本高，容易被异常报价误导。  
**现有做法不足**：纯人工比价慢；纯聊天机器人无法基于本地房源库做可复核估价。  
**项目范围**：交付可运行端到端原型——输入约束后，自动查询房源、用回归模型估计公允租金、给出偏贵/合理/偏便宜建议；高偏差触发人工复核。不做自动签约。  
**成功标准**：
1. 返回可检查结果（有列表或明确无匹配）；
2. 启用模型时输出预测价与建议标签；
3. 输入异常/无匹配/高偏差可处置；
4. 测试集上回归误差优于“均单价×面积”基线；任务样例可复现通过。

## 2. 方案与系统设计
Agent 采用“编排器 + Skill + 数据工具 + ML 模型”结构：
1. `RentAgent`（`src/agent_core.py`）负责任务入口校验、步骤状态、成功判定与安全策略；
2. `RentFilterSkill` 负责硬约束筛选、调用模型、生成建议；
3. 本地 CSV 房源库作为检索/数据工具；
4. scikit-learn Pipeline 提供租金回归。

备选方案曾考虑仅做命令行或仅规则筛选；最终保留 CLI 便于调试，以 Streamlit 网页作为正式任务入口，并用消融开关证明 ML 贡献。

## 3. 机器学习方法
**任务类型**：租金回归（课程模块：租金或需求预测）。  
**特征**：面积、居室、厅数、是否地铁相关、经纬度、朝向、行政区。  
**模型**：LinearRegression / Ridge / Lasso；验证集选优后在测试集评估。  
**训练/推理**：离线训练保存 `models/best_model.joblib`；Agent 在线推理。  
**基线**：按租类型中位单价 × 面积。  
**贡献**：没有回归预测，Agent 只能按预算过滤，无法回答“值不值这个价”。

- 指标：MAE、RMSE、R²、MAPE；另报告任务完成率与样例通过率  
- 对照：三模型 + 基线；消融关闭模型  
- 失败案例：测试集百分比误差最大样本（`failure_cases.csv`）  
- 结论应写清：模型相对基线的改进、在哪些区域/户型误差大、行政区近似带来的限制  

## 6. 讨论与改进
真实使用价值：可辅助学生快速排除明显不合理报价。  
风险边界：历史价格漂移；线性模型对极端房源失效；行政区 GPS 粗分可能错分。  
改进：引入小区级特征、分位数回归给区间预测、更新近半年数据、增加看房成本/通勤约束。
